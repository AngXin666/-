## 1. 启动与入口

### 1.1 入口职责
- 主入口文件：`run.py`
- 主要职责：
  - 处理控制台编码与日志基础设置
  - 清理旧 Python 进程实例（避免重复运行）
  - 许可证校验
  - 初始化模拟器/ADB
  - 启动 GUI

### 1.2 核心流程
1. `main()` 调用 `close_old_instances()` 清理旧实例。  
2. `SimpleLicenseManager.check_license()` 校验激活状态。  
3. 读取 `config.yaml`，初始化 `EmulatorController`，获取 ADB 路径。  
4. 创建 `ADBBridge`。  
5. 调用 `src/gui.py` 的 `main(adb_bridge=adb)` 进入 GUI 主循环。  

### 1.3 异常处理
- 顶层 `try/except/finally`：
  - 写入 `error.log`
  - 弹窗显示错误
  - 最终尝试释放模型资源（`ModelManager.cleanup()`）

## 2. GUI 主控与调度

### 2.1 入口类
- 文件：`src/gui.py`
- 主类：`AutomationGUI`

### 2.2 GUI 的实际定位
- 该类不仅是界面层，还承担：
  - 运行控制（开始/暂停/停止）
  - 账号分配与并发调度
  - 单账号执行流程串联
  - 统计更新、日志显示、结果入库触发

### 2.3 关键函数
- `_start_automation`：启动前检查、状态重置、线程启动。
- `_run_automation_thread`：后台线程包装异步主流程。
- `_run_automation_async`：实例检测、账号集合构建、并发执行组织。
- `_process_account_with_instance`：单账号核心处理链路（连接设备、启动流程、执行业务工作流）。

### 2.4 并发模型
- 线程 + `asyncio` 混合：
  - GUI 主线程负责 Tk 事件循环
  - 后台线程内运行异步任务
  - 每个实例/账号通过异步方法执行

## 3. 模拟器与 ADB 控制

### 3.1 模拟器控制
- 文件：`src/emulator_controller.py`
- 职责：
  - 自动检测 MuMu 安装路径
  - 启动/检测实例
  - 获取实例 ADB 端口
  - 分辨率检查

### 3.2 ADB 桥接
- 文件：`src/adb_bridge.py`
- 职责：
  - 封装 `connect/shell/tap/swipe/start_app/stop_app/screencap` 等命令
  - 统一异步执行（`_run_adb_async`）
  - 添加超时与重试策略
  - ADB 服务器异常时支持冷却重启

### 3.3 关键设计点
- 单账号处理时创建独立 `ADBBridge` 对象，减少设备间干扰。
- 对高频不稳定命令（`shell`、`stop_app`）加重试，降低偶发超时导致的失败。

## 4. 模型管理与检测体系

### 4.1 模型管理
- 文件：`src/model_manager.py`
- 模式：单例（`ModelManager.get_instance()`）
- 职责：
  - 统一加载模型和 OCR 线程池
  - 对外提供共享实例（避免重复加载）
  - 提供加载统计、配置合并、模型可用性检查

### 4.2 检测体系分层
- `src/page_detector_dl.py`：页面分类（启动/登录/签到/资料等状态）
- `src/page_detector_integrated.py`：YOLO 元素检测（按钮/目标元素）

### 4.3 使用策略
- 先判页面状态，再做元素检测与点击。
- 检测结果可缓存，减少重复截图和推理开销。

## 5. 登录与缓存登录

### 5.1 登录主逻辑
- 文件：`src/auto_login.py`
- 核心函数：
  - `login(...)`
  - `_do_normal_login(...)`
  - `navigate_to_login(...)`
  - `logout(...)`

### 5.2 登录流程
1. 判断页面状态。  
2. 如可用，优先走缓存登录。  
3. 缓存不可用时执行普通登录（输入账号密码、协议勾选、点击登录）。  
4. 登录后校验页面是否进入成功状态（如个人页/积分页后续处理）。  

### 5.3 缓存管理
- 文件：`src/login_cache_manager.py`
- 关键函数：
  - `save_login_cache`
  - `restore_login_cache`
  - `has_cache`
  - `clear_app_login_data`
- 逻辑要点：
  - 支持缓存加密
  - 维护手机号到 `user_id` 的映射
  - 后续流程会做 `user_id` 一致性校验，防止错绑缓存

## 6. 单账号业务工作流

### 6.1 工作流主函数
- 文件：`src/ximeng_automation.py`
- 函数：`run_full_workflow(device_id, account, skip_login=False, workflow_config=None)`

### 6.2 执行步骤（按代码顺序）
1. 登录（可跳过，缓存命中时进入）。  
2. 获取个人资料（快速模式会根据缓存存在与否决定是否跳过）。  
3. 执行签到。  
4. 设置最终余额。  
5. 检查并执行自动转账。  
6. 退出登录并收尾。  

### 6.3 流程开关
- 由 `workflow_config` 控制：
  - `enable_login`
  - `enable_profile`
  - `enable_checkin`
  - `enable_transfer`

### 6.4 关键失败分支
- 登录失败：直接返回 `AccountResult(success=False)` 并写入错误类型。  
- 资料读取连续失败：终止流程。  
- 签到失败/异常：当前版本直接返回失败，不再继续后续步骤。  
- 转账失败：记录失败信息与失败原因，保留账号级结果。  

## 7. 资料读取（ProfileReader）

### 7.1 模块职责
- 文件：`src/profile_reader.py`
- 从个人页读取：
  - `nickname`
  - `user_id`
  - `balance`
  - `points`
  - `vouchers`

### 7.2 核心函数
- `get_full_profile_with_retry`
- `get_full_profile_parallel`
- 多个字段级 fallback（如 `get_balance_fallback`、`get_user_id_fallback`）

### 7.3 逻辑特点
- OCR + 规则提取结合。
- 允许并行识别与重试。
- 对异常文本有过滤和置信策略，尽量避免脏数据写入主结果。

## 8. 签到流程（DailyCheckin）

### 8.1 主入口
- 文件：`src/daily_checkin.py`
- 函数：`do_checkin(...)`

### 8.2 签到逻辑
1. 检测当前页面状态。  
2. 导航到签到入口并执行点击。  
3. 循环处理签到、弹窗和次数判断。  
4. 汇总签到奖励、签到后余额、签到总次数。  
5. 返回结构化结果给工作流主函数。  

### 8.3 与主流程的协作
- `run_full_workflow` 会在签到前准备 `profile_data`。  
- 若缓存失效导致跳登录页，可通过回调触发登录恢复。  

## 9. 自动转账流程（BalanceTransfer）

### 9.1 主入口
- 文件：`src/balance_transfer.py`
- 函数：`transfer_balance(...)`

### 9.2 转账执行逻辑
1. 定位余额/转账入口。  
2. 输入收款 ID 和金额。  
3. 解析并校验确认弹窗。  
4. 提交转账。  
5. 回读余额确认结果。  

### 9.3 配置与策略
- 配置文件逻辑：`src/transfer_config.py`
- 选择策略：`src/recipient_selector.py`
- 历史记录：`src/transfer_history.py`

### 9.4 结果处理
- 成功：写入转账记录，并更新 `AccountResult.transfer_amount/recipient`。  
- 失败：保留失败原因，写失败记录，供后续排查与补偿。

## 13. 当前架构特点（开发视角）

### 13.1 优势
- 功能完整，覆盖登录缓存、签到、转账、数据追踪闭环。
- 线上问题修复经验多，容错与重试路径较丰富。

### 13.2 风险点
- `src/gui.py` 体量大且耦合重，维护成本高。
- 流程分支复杂，行为回归风险高。
- 工作树活跃，开发时必须保持小步改动。

### 13.3 建议
1. 优先稳定关键链路（ADB/模拟器/登录判定）。  
2. 将单账号处理从 GUI 分拆到 service 层。  
3. 为关键适配层补最小自动化测试。
